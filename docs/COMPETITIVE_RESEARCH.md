## 4. ما التقنيات التي يستخدمونها؟ (الهندسة تحت الغطاء)

### أ) بوابة النماذج والتوجيه (قلب منصتنا — مثبت أننا على الطريق الصحيح)
المنصات الجادة لا تستدعي مزوداً واحداً مباشرة؛ تستخدم طبقة Gateway:
- **OpenRouter**: مجمّع 300-500 نموذج بمفتاح واحد + توجيه تلقائي عند فشل المزود + رسم 5.5% على الشحن.
- **LiteLLM** (OSS, 33.8K★): بروكسي OpenAI-compatible لـ 100+ مزود مع **fallbacks، budgets، مفاتيح افتراضية، rate limits، Redis caching**.
- **Portkey**: بوابة مدارة مع **دوائر كسر، حراسة (Guardrails)، semantic caching، سجلات ولوحات تكلفة** — SOC2/ISO.
- **Cloudflare/Vercel AI Gateway**: توجيه + كاش على الحافة + مراقبة إنفاق.
- **Maestro / RouteLLM / Not Diamond**: "الراوتر الذكي" — يختار أرخص/أفضل نموذج لكل طلب.

> ✅ **هذا بالضبط ما بنيناه بالفعل** في `packages/ai-gateway`: 5 استراتيجيات توجيه (منها smart-auto بنفس فلسفة RouteLLM) + دوائر كسر بتبريد تصاعدي (فلسفة Portkey) + سلاسل Fallback (فلسفة LiteLLM) + عدادات وتكلفة لكل رسالة. **الفرق أننا نراهن أكثر على النماذج المجانية (OpenRouter :free / Groq / Gemini / NVIDIA) بينما كل هؤلاء يحاسبون على كل رمز.**

### ب) الـ RAG (استرجاع المعرفة)
- الجميع يستخدم النمط نفسه: Chunking → Embeddings → **قاعدة متجهات** → استرجاع top-k → ضخ في البرومبت.
- قواعد المتجهات الشائعة: **Pinecone** (Chatbase), **pgvector** (CustomGPT/معظم), Qdrant/Weaviate (Botpress, Flowise).
- SiteGPT يميّز نفسه بـ **auto-sync**: إعادة زحف الموقع يومياً/أسبوعياً حتى لا تتقادم المعرفة.
- ✅ عندنا: RAG-lite بكلمات مفتاحية (يعمل الآن). 🔲 الترقية المخططة: **pgvector + زحف روابط + auto-refresh** (نفس ميزة SiteGPT المميزة).

### ج) الودجت والدمج
- الأغلبية: `<script>` يحقن iframe (Chatbase, SiteGPT, Intercom Messenger, Tidio, Crisp كلها iframe/Shadow DOM لتفادي تعارض CSS).
- البعض يقدم حزمة React/JS SDK رسمية (Intercom, Crisp, Tidio).
- ✅ عندنا: iframe sandbox + Shadow DOM + محمّل 8KB + توقيع جلسات HMAC + تحقق Origin — **مطابق لمعايير الأكبر منهم، وأخف**.

### د) المراقبة والفوترة الداخلية
- **Stammer**: "محفظة الوكالة" — رصيد مسبق يُخصم لكل رسالة حسب النموذج المختار، وعملاء فرعيون بمحافظ خاصة يدفعون لك مباشرة بعلامة مضافة (يشترون بـ $0.01 ويبيعون بـ $0.05!).
- **Intercom**: يحاسب **لكل حل ناجح** $0.99 — "النتيجة" تعني أن العميل لم يطلب بشراً بعد إجابة Fin.
- ✅ عندنا: عدّ أحداثي لكل رسالة (توكنز/تكلفة/زمن/مزود) + مصالحات + حدود عميل — **البنية جاهزة لأي نموذج تسعير** (رسائل/توكنز/لكل-حل). 🔲 ناقص: شاشة "محفظة" وبيع الرصيد للعملاء الفرعيين.

### هـ) التقنيات الشائعة في بنيتهم
| الطبقة | الأكثر استخداماً |
|---|---|
| الواجهة | React + Tailwind (الغالبية) |
| الخلفية | Node (NestJS/Express) — Python (FastAPI) عند Botpress/Rasa |
| القاعدة | PostgreSQL + Redis (الغالبية) — ClickHouse للتحليلات الضخمة |
| المتجهات | Pinecone / pgvector / Qdrant |
| الطوابير | BullMQ / Celery / Temporal |
| المراقبة | Langfuse / Helicone / Sentry + Grafana |
| النشر | Docker/K8s + CDN (Cloudflare) |

> ✅ مكدسنا (TS + NestJS + Next.js + Postgres/SQLite + Redis + Preact) **يطابق مكدس المنصات الناجحة تماماً** — لا حاجة لتغيير أي قرار تقني.

## 6. الخلاصة التنفيذية

1. **منتجنا مطابق لأعلى معايير الفئة A** (Chatbase/SiteGPT) في: البوت المخصص، الثيم، التدريب بالمعرفة، التحليلات، الودجت الآمن — ومتفوق في **بوابة النماذج والاقتصاد المجاني** الذي لا يملكه أحد.
2. **نموذجنا التجاري الصحيح هو نموذج الوكالة** (Stammer): بيع باقات للعملاء بـ $40-80/شهر بأقل من المنافسين العالميين، بهامش ممتاز بفضل تكلفتنا شبه الصفرية، مع إزالة شعار مجانية (المنافسون يتقاضون عليها $99-199!).
3. **أول 3 ميزات يجب تنفيذها** (سبق وقمنا بتنفيذ #1 في هذه الجلسة): Lead Capture ✅ ثم زحف الروابط ثم التحويل البشري — هذه الثلاثة تجعل عرضنا مكتملاً تجارياً أمام أي عميل.
