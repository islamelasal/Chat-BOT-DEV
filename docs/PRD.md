## 1. الملخص التنفيذي

**Chat Bot Dev** منصة SaaS متعددة المستأجرين (Multi-Tenant) تتيح لنا إنشاء بوتات ذكاء اصطناعي وإدارتها وتوزيعها على مواقع العملاء عبر **سطر كود واحد** يضعه العميل في موقعه. البوت يظهر داخل موقع العميل بإطار آمن ومعزول، بهوية بصرية مطابقة لهوية العميل (Thème مخصص لكل عميل)، ويتفاعل مع زوّار الموقع بسياق ذكي حسب الصفحة التي يتواجد فيها الزائر.

النواة التقنية للمنصة هي **بوابة ذكاء اصطناعي موحّدة (AI Gateway)** تدير مزودي النماذج (OpenRouter، Groq، Gemini، NVIDIA، DMXAPI، AIMLAPI… إلخ) بمفاتيح مشفرة، مع **محرك توزيع أحمال احترافي (Load Balancer)** و**Failover ذكي** و**دوائر كسر (Circuit Breakers)** و**نبضات مراقبة (Heartbeats)** و**عدادات استهلاك** تعمل على مدار الساعة حتى لو لم يكن الموقع الإداري مفتوحاً — لضمان استمرارية الخدمة، والتنقل السلس بين الخدمات المجانية والمدفوعة دون انقطاع.

### القيمة الأساسية
1. **للعملاء:** بوت احترافي يرفع التحويلات ويجيب عن الأسئلة 24/7 بهوية موقعهم، بدون أي خبرة برمجية.
2. **للمنصة:** سيطرة مركزية على النماذج والتكاليف والجودة — نستخدم النماذج المجانية حيثما أمكن وننتقل للمدفوعة بذكاء عند الحاجة، مع محاسبة دقيقة لكل عميل.
3. **للتوسع:** كل مكوّن (بوابة، عداد، ثيم، ودجت) مصمم ليكون قابلاً للتوسع أفقياً منذ اليوم الأول.

## 2. الرؤية والأهداف

### الرؤية
> أن نكون طبقة التشغيل الذكية بين مواقع العملاء وأفضل نماذج الذكاء الاصطناعي في العالم — بأقل تكلفة وأعلى جودة وأمان.

### الأهداف الاستراتيجية (SMART)
| # | الهدف | القياس المستهدف |
|---|---|---|
| G1 | إطلاق MVP خلال **3 أسابيع** | Go-Live لأول عميل (الشوا) |
| G2 | توفر الخدمة | ≥ 99.9% شهرياً |
| G3 | كفاءة التكلفة | ≥ 60% من الاستهلاك عبر مزودين مجانيين بدون تدهور جودة ملموس |
| G4 | زمن أول رد | TTFT ≤ 800ms (P95) عبر البوابة |
| G5 | انعدام الانقطاع عند فشل مزود | Failover تلقائي ≤ 2 ثانية |
| G6 | دقة العدادات | انحراف ≤ 0.5% عن فواتير المزودين |
| G7 | إضافة عميل جديد | ≤ 30 دقيقة (ثيم + معرفة + نشر) |
| G8 | إضافة مزود API جديد | ≤ ساعة واحدة بدون تعديل كود (Configuration-Only) |

## 3. المشكلة والحل

| المشكلة | الحل في Chat Bot Dev |
|---|---|
| مزودو الـ LLM المجانيون يتغيرون باستمرار (حدود، إيقاف، تغيير نماذج) | طبقة تجريد موحّدة + مراقبة حية + تنقّل تلقائي بين المزودين |
| كل عميل يحتاج بوتاً بهوية مختلفة | نظام ثيمات لكل عميل + معاينة حية |
| مواقع مختلفة (CS-Cart، WordPress، HTML…) | ودجت معزول يعمل على أي منصة بنفس المقتطف |
| الخوف من إظهار مفاتيح الـ API في واجهة الزائر | المفاتيح في الخادم فقط، مشفرة، والزائر يتحدث مع البوابة فقط |
| لا يوجد عدّ دقيق للاستهلاك | نظام عدّادات أحداثي (Event-Sourced) مع تسوية دورية |
| بوت عام لا يفهم سياق الصفحة | الودجت يرسل سياق الصفحة (مسار، عنوان، فئة منتج) للبوت |

## 4. جمهور المنتج (Personas)

1. **مالك المنصة (Admin/Super Admin):** يدير كل شيء — العملاء، المزودين، الفوترة، الأمان.
2. **مشغّل المنصة (Operator):** يتابع النبضات والعدادات والتنبيهات ويصلح الأعطال.
3. **العميل (Client):** يستلم مقتطف الكود ويشاهد تقارير بوتّه.
4. **زائر موقع العميل (End Visitor):** المستخدم النهائي الذي يتحدث مع البوت.
5. **مطوّر المنصة (Developer):** يضيف مزودين/نماذج/ميزات جديدة.

## 5. نطاق المنتج

### داخل النطاق (MVP → v1)
- لوحة تحكم إدارية كاملة (RTL/عربي)
- إدارة العملاء + ملف براند لكل عميل (شعار، ألوان، خطوط)
- إنشاء بوتات متعددة لكل عميل (شخصية، برومبت، معرفة، سلوك)
- مولّد الثيم الحي (ألوان/مواضع/نصوص/أيقونات)
- مقتطف تضمين + إدارة إصدارات الودجت
- بوابة AI موحّدة: مزودون (OpenAI-compatible + Gemini native)، مفاتيح مشفرة، سجل نماذج وأسعار
- محرك توجيه: أولوية/Failover، موازنة مرجّحة، دائرة كسر، فحوصات صحية، سقوف حصص
- محرك نبضات + عدادات استهلاك + تنبيهات (Telegram/Email)
- سجل محادثات + تحليلات + تقييم جودة الردود
- حماية: نطاقات مسموحة، حدود معدل، فلترة Prompt Injection، تدقيق أمني (Audit Log)
- RBAC (أدوار وصلاحيات)

### خارج النطاق (مراحل لاحقة)
- فوترة مالية فعلية (Stripe/Paymob) — v1.x
- Handoff بشري (تحويل لموظف/واتساب) — v1.x
- سوق ثيمات عام + API عامة لعملاء B2B — v2
- تدريب/ضبط نماذج خاصة (Fine-tuning) — v2
- تطبيق موبايل للإدارة — v3

## 6. المصطلحات (Glossary)

| المصطلح | التعريف |
|---|---|
| **Client / Tenant** | عميل المنصة (صاحب الموقع) |
| **Bot** | إعداد ذكاء اصطناعي محدد (شخصية+معرفة+سلوك+نموذج) مرتبط بعميل |
| **Widget** | ملف JS يُضمَّن في موقع العميل ويعرض نافذة المحادثة |
| **Provider** | مزود خدمة نماذج (OpenRouter, Groq, Gemini, DMXAPI…) |
| **Model** | نموذج لغوي محدد (مثلاً: `meta-llama/llama-3.3-70b-instruct`) |
| **Gateway** | خدمتنا التي تستقبل طلبات البوت وتوجّهها للمزود الأنسب |
| **Routing Policy** | سياسة اختيار النموذج/المزود لكل بوت |
| **Failover Chain** | سلسلة بدائل مرتبة يُنتقل إليها عند فشل المرشح الحالي |
| **Circuit Breaker** | حجب مؤقت لمزود/نموذج متعطل مع فحص نصف-مفتوح |
| **Heartbeat / Pulse** | فحص دوري مجدول يتحقق أن المزود/الخدمة حية |
| **Metering** | عدّ استهلاك (طلبات، توكنز، تكلفة) لكل عميل/بوت/نموذج |
| **Quota Headroom** | ما تبقى من حصة المزود/العميل قبل النفاد |

## 7. المتطلبات الوظيفية (FR)

> الأولوية: **P0** = إطلاق MVP، **P1** = بعد الإطلاق مباشرة، **P2** = توسعات.

### 7.1 المصادقة وإدارة الفريق
- **FR-001 (P0):** تسجيل دخول إداري (بريد + كلمة مرور Argon2id) + JWT قصير العمر + Refresh Token دوّار.
- **FR-002 (P0):** 2FA عبر TOTP (Google Authenticator) إجباري لحسابات Super Admin واختياري للبقية.
- **FR-003 (P0):** أدوار: `super_admin`، `operator`، `support`، `client_viewer` مع مصفوفة صلاحيات.
- **FR-004 (P0):** سجل تدقيق (Audit Log) لكل: دخول، تعديل، حذف، تغيير إعدادات حرجة.
- **FR-005 (P1):** جلسات متعددة الأجهزة + تسجيل خروج عن بُعد.

### 7.2 إدارة العملاء (Clients)
- **FR-010 (P0):** CRUD عميل: الاسم، الدومين، البريد، الهاتف، الحالة (نشط/موقوف/تجريبي).
- **FR-011 (P0):** ملف براند (Brand Kit): شعار (رفع)، الألوان (رئيسي/ثانوي/خلفية/نص)، الخط، الشعار في رأس المحادثة.
- **FR-012 (P0):** قائمة نطاقات مسموحة (Allowlist) — البوت لا يعمل إلا عليها + نطاقات محظورة.
- **FR-013 (P0):** باقات العميل: `free` / `starter` / `pro` / `enterprise` مع حدود (محادثات/شهر، توكنز/شهر، بوتات، نطاقات).
- **FR-014 (P1):** تقارير عميل (يمكن مشاركة رابط قراءة فقط مع العميل لاحقاً).

### 7.3 إدارة البوتات (Bots)
- **FR-020 (P0):** إنشاء عدة بوتات لكل عميل (مثال: بوت مبيعات + بوت دعم فني).
- **FR-021 (P0):** محرر الشخصية: System Prompt منظم (هوية، نبرة، حدود، قواعد)، مع **قوالب جاهزة** (متجر إلكتروني، مطعم، شركة…).
- **FR-022 (P0):** قاعدة معرفة (Knowledge Base): رفع مستندات (PDF/DOCX/TXT/CSV) + روابط صفحات + نص حر، مع تقسيم (Chunking) وRAG على مستوى البوت.
- **FR-023 (P0):** التحكم بالسلوك: مواضيع مسموحة/ممنوعة، كلمات مرشحة، أقصى طول رد، لغة البوت (ar/en/ثنائي).
- **FR-024 (P0):** ربط البوت بسياسة توجيه (Routing Policy) + نموذج افتراضي + سلسلة Fallback.
- **FR-025 (P0):** إعدادات ترويجية: بطاقات اقتراح أسئلة سريعة، رسالة ترحيب، وضع الصمت.
- **FR-026 (P1):** مسارات/أهداف (Flows): توجيه نحو صفحة منتج/عرض، جمع إيميل، تحويل لمندوب.
- **FR-027 (P1):** اختبار البوت داخل لوحة التحكم (Playground) قبل النشر.
- **FR-028 (P2):** إصدارات البوت (Draft/Published) مع إمكانية الرجوع.

### 7.4 الثيم ومولّد الودجت (Theme Builder)
- **FR-030 (P0):** تخصيص كامل: الألوان، موضع الفقاعة (يمين/يسار/أسفل)، شكلها (دائرة/زر بنص)، نافذة كاملة أو صغيرة، الخط والاتجاه RTL/LTR.
- **FR-031 (P0):** معاينة حية (Live Preview) بصفحة وهمية قبل النشر.
- **FR-032 (P0):** قواعد ظهور: عند التحميل / بعد X ثانية / نية الخروج / تمرير % / حسب الصفحة.
- **FR-033 (P0):** استهداف صفحات: الكل، أو مسارات محددة/مستبعدة (regex) — مثلاً في CS-Cart: صفحات المنتج فقط.
- **FR-034 (P0):** مقتطف التضمين جاهز للنسخ مع تعليمات لكل منصة (CS-Cart، WordPress، HTML…).
- **FR-035 (P1):** إصدارات ودجت (Widget Versions) مع نشر تدريجي (canary 10% → 100%) وزر رجوع فوري.
- **FR-036 (P2):** متعدد اللغات للودجت (ترجمة نصوص الواجهة ar/en).

### 7.5 بوابة الذكاء الاصطناعي (AI Gateway)
- **FR-040 (P0):** إدارة مزودين: إضافة/تعديل/تعطيل مزود بـ (اسم، Base URL، نوع، مفتاح API **مشفّر**، حالة، حدود).
- **FR-041 (P0):** أنواع المزودين: `openai-compatible` (يغطي ~90% من المزودين) + `gemini-native` — قابل للتوسع بأنواع جديدة بدون تغيير كود.
- **FR-042 (P0):** سجل نماذج لكل مزود (جلب تلقائي من `/models` + إدخال يدوي) مع: سياق، تكلفة (لكل 1M توكنز)، تصنيف (free/paid)، حالة.
- **FR-043 (P0):** اختبار اتصال/رسالة تجريبية من اللوحة لأي نموذج.
- **FR-044 (P0):** البث المباشر (Streaming SSE) من المزود إلى الودجت دون تخزين وسيط.
- **FR-045 (P1):** مجموعات مفاتيح (Key Pools) للمزود الواحد مع تناوب تلقائي عند تجاوز الحدود.

### 7.6 محرك التوجيه والموازنة (Routing & Load Balancing) — قلب المنصة
- **FR-050 (P0):** سياسات توجيه لكل بوت: `priority-failover` (افتراضي) / `weighted-round-robin` / `least-latency` / `cheapest-first` / `smart-auto` (درجة مركّبة من الصحة+التأخير+التكلفة+المتبقي).
- **FR-051 (P0):** سلسلة بدائل (Fallback Chain) مرتبة لكل بوت: نموذج رئيسي → بديل → طوارئ، مع تنقّل تلقائي عند: خطأ مزود، تجاوز مهلة، نفاد حصة، دائرة مفتوحة.
- **FR-052 (P0):** دائرة كسر (Circuit Breaker) لكل زوج (مزود×نموذج): `CLOSED→OPEN` عند معدل خطأ > 50% (نافذة 2 دقيقة) أو 5 فشل متتالي، `OPEN→HALF_OPEN` بعد مهلة تبريد تصاعدية، فحص برسالة تجريبية.
- **FR-053 (P0):** مقاييس صحة حية لكل مزود: زمن استجابة EWMA، معدل نجاح، معدل خطأ 4xx/5xx/429.
- **FR-054 (P0):** **إدراك الحصص (Quota Awareness):** قراءة ترويسات `x-ratelimit-*` + حدود معروفة لكل مزود → تحويل مروري استباقي قبل النفاد.
- **FR-055 (P0):** إعادة محاولة (Retry) مع تراجع أسي + jitter لمرة واحدة على مزود بديل فقط (لا ازدواجية فوترة).
- **FR-056 (P0):** مهلات تكيفية: مهلة أول بايت (TTFT) لكل نموذج حسب بياناته التاريخية.
- **FR-057 (P1):** وضع "الاقتصاد": يفضّل المزودين المجانيين طالما الجودة ضمن حد مقبول، ويصعد للمدفوع فقط عند تعطل/تدهور المجاني.
- **FR-058 (P1):** تنبيه فوري عند استنفاد كل البدائل لبوت (Telegram + Email).

### 7.7 النبضات والمراقبة الدائمة (Heartbeats) — تعمل 24/7
- **FR-060 (P0):** خدمة عمال خلفية (Worker) منفصلة عن الموقع الإداري تعمل دائماً (حتى واللوحة مغلقة).
- **FR-061 (P0):** نبضة دورية لكل مزود نشط كل 30–120 ثانية (رسالة مصغّرة أو استدعاء `/models`) → سجل نبضات + مفتاح TTL في Redis.
- **FR-062 (P0):** **Dead-Man Switch:** إذا انقضى TTL دون تجديد (العامل ميت) → تنبيه فوري تلقائي.
- **FR-063 (P0):** لوحة "حالة النظام" الحية: نبض كل مزود/نموذج/خدمة (أخضر/أصفر/أحمر) + آخر نبضة.
- **FR-064 (P0):** فحوصات صحية داخلية: `/healthz` و `/readyz` + فحص خارجي (Uptime Kuma) بضرب نقطة عامة كل دقيقة.
- **FR-065 (P1):** إعادة تشغيل تلقائي للعمال المعطلة (supervisor/restart policy) + إحصائيات زمن التعطل.

### 7.8 العدادات والاستهلاك (Metering & Billing-ready)
- **FR-070 (P0):** عدّ لكل حدث دردشة: `(client, bot, model, provider, tokens_in, tokens_out, latency, status, cost, visitor_id)`.
- **FR-071 (P0):** عدادات Redis لحظية (يوم/شهر، لكل بوت ولكل مزود) + تجميع دوري للـ PostgreSQL (Rollups ساعية/يومية).
- **FR-072 (P0):** لوحات: استهلاك اليوم/الشهر، تكلفة تقديرية، أكثر النماذج استخداماً، مقارنة مجاني/مدفوع.
- **FR-073 (P0):** **مصالحات (Reconciliation):** جدول دوري يقارن عداداتنا بسجلات/فواتير المزود عند توفرها (أو إجمالي الاستخدام API) ويُظهر الانحراف.
- **FR-074 (P0):** حدود للعميل: توكنز/محادثات يومية وشهرية + عند 80% تنبيه، عند 100% رسالة اعتذار للزائر أو تحويل تلقائي للنموذج المجاني.
- **FR-075 (P1):** تصدير تقارير CSV/PDF + تنبيهات تكلفة شهرية.
- **FR-076 (P2):** فوترة آلية للعملاء (فاتورة بالاستهلاك) — الربط المالي في مرحلة لاحقة.

### 7.9 المحادثات والتحليلات
- **FR-080 (P0):** سجل محادثات قابل للبحث (عميل، بوت، تاريخ، كلمة) مع عرض الرسائل كاملة.
- **FR-081 (P0):** إحصائيات: عدد محادثات، رسائل/محادثة، مدة، تقييم 👍/👎 من الزائر، أسئلة بلا إجابة (تتجمع لتحسين المعرفة).
- **FR-082 (P1):** وضع المتابعة الحية (Live Inbox) مع إمكانية رد إداري (يتحول البوت لـ co-pilot) — أساس الـ Handoff.
- **FR-083 (P1):** تحليل مشاعر/NPS بسيط + أكثر الكلمات تكراراً.

### 7.10 الإشعارات والتنبيهات
- **FR-090 (P0):** قنوات: Telegram Bot + Email (SMTP/Resend).
- **FR-091 (P0):** أنواع تنبيه: مزود سقط، حصة شارفت على النفاد، دائرة فُتحت، كل البدائل مستنفدة، عامل متوقف، خطأ 5xx متكرر، تجاوز حد عميل.
- **FR-092 (P0):** تجميع (Debounce): نفس التنبيه لا يتكرر قبل 15 دقيقة إلا إذا تدهور.

### 7.11 الأمان التطبيقي (Security Requirements)
- **FR-100 (P0):** مفاتيح المزودين مشفرة AES-256-GCM (مغلفة بمفتاح KMS) ولا تظهر أبداً في الواجهة أو اللوغات.
- **FR-101 (P0):** التحقق من مصدر الطلب للودجت: `Origin/Referer` ضد قائمة نطاقات العميل + توقيع جلسة.
- **FR-102 (P0):** حدود معدل للزائر (لكل IP + لكل جلسة): نافذة منزلقة في Redis.
- **FR-103 (P0):** فلترة هجمات الحقن (Prompt Injection) على مدخلات الزائر + قائمة أنماط + طبقة نموذج مصغّر (اختياري).
- **FR-104 (P0):** فلترة المخرجات: ألفاظ/مواضيع ممنوعة حسب سياسة العميل + حد أقصى لطول الرد.
- **FR-105 (P0):** تشفير كامل أثناء النقل (TLS 1.2+) + HSTS + CSP صارم على الودجت (sandbox iframe).
- **FR-106 (P0):** إخفاء بيانات الزائر الحساسة: لا تخزين IP خام (تجزئة)، ولا كشف مفاتيح، حد احتفاظ للمحادثات (configurable, default 90 يوم).
- **FR-107 (P1):** حماية CSRF + توقيع HMAC للـ Webhooks + تدوير مفاتيح.

## 8. المتطلبات غير الوظيفية (NFR)

| المجال | المتطلب |
|---|---|
| الأداء | تحميل الودجت (TTFF) ≤ 150ms من CDN؛ أول توكن من البوت ≤ 800ms P95؛ زمن لوحة تحكم ≤ 300ms P95 |
| التوفر | 99.9% شهرياً؛ النبضات والعدادات لا تتوقف بتوقف اللوحة |
| قابلية التوسع | API عديمة الحالة (أفقي)؛ قائمة انتظار للبوابة مع backpressure؛ DB بقراءة منفصلة عند >100K حدث/يوم |
| السعة | تحمّل 500 محادثة متزامنة لكل عقدة API واحدة في الإصدار الأول |
| الأمان | توافق OWASP ASVS L2 للمساحات الحرجة؛ اختبار اختراق قبل v1.0 |
| الخصوصية | حد أدنى من البيانات الشخصية؛ حذف عند الطلب؛ توافق GDPR كمرجعية حتى لو كان التشغيل مصرياً |
| المتابعة | OpenTelemetry + Sentry + Grafana + لوحات جاهزة (النموذج الأدنى: Sentry + Grafana + Loki) |
| التوافق | المتصفحات: آخر نسختين من Chrome/Safari/Firefox/Edge + دعم iOS Safari |
| الصيانة | نشر CI/CD آلي (GitHub Actions)، ترحيلات DB مُدارة، نسخ احتياطي يومي (DB+ملفات) باحتفاظ 30 يوم |

## 9. تجربة المستخدم (UX/UI)

- الواجهة الإدارية **عربية RTL بالكامل** كافتراضي مع جاهزية LTR.
- نظام تصميم موحّد (Design Tokens): ألوان، مسافات، تيبوغرافيا (Inter/Cairo)، مكونات shadcn/ui.
- الشاشات الرئيسية: Dashboard عام → العملاء → بوتات → بوابة AI → الحالة/النبضات → المحادثات → التقارير → الإعدادات.
- مبدأ "شاشة واحدة لكل مهمة": إنشاء بوت خلال ≤ 4 خطوات.
- الودجت: حركة فتح سلسة، رسائل متدفقة token-by-token، مؤشر كتابة، حالة اتصال، زر تصغير/إغلاق، تحية بالاسم عند توفره.
