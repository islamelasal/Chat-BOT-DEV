# 🕷️ تكامل Scrapling — تجاوز الحماية في زحف الروابط

> **بحث (أغسطس 2026):** [D4Vinci/Scrapling](https://github.com/D4Vinci/Scrapling) — ★75,000 · Python · BSD-3 · محدّث يومياً.

## ما هو؟
إطار زحف متكيّف (Adaptive) يحل بالضبط المشكلة التي واجهناها مع **elshawwa.com** (محمي بـ Cloudflare):

| الإمكانية | الفائدة لنا |
|---|---|
| **StealthyFetcher** | يتجاوز Cloudflare Turnstile/Interstitial — المواقع المحمية أصبحت قابلة للتدريب |
| **Fetcher (HTTPX)** | طلبات ببصمة TLS متصفح + HTTP/3 — سريع بلا متصفح للمواقع العادية |
| **adaptive=True / auto_save** | العناصر تتبع نفسها عند تغيّر تصميم الموقع — زحفنا المستقبلي للكتالوجات يبقى سليماً بعد تحديثات عملاء CS-Cart |
| **Spiders** | زحف كامل متزامن مع throttle تلقائي + روبوتات txt + SitemapSpider + ShopifySpider |
| **MCP Server + Agent Skill** | جاهز للذكاء الاصطناعي |
| **Docker جاهز** | `pyd4vinci/scrapling` بكل المتصفحات |

## الدراسة العميقة للكود المصدري — ما تعلمناه وطبقناه

درست ملفات المصدر الفعلية (مش README فقط): `engines/static.py`،
`engines/_browsers/_stealth.py`، `spiders/throttle.py`، `docs/spiders/proxy-blocking.md`.

### خريطة: تقنية Scrapling → تطبيقنا

| # | التقنية في Scrapling | كيف فهمناها | تطبيقنا (v2) |
|---|---|---|---|
| 1 | **TLS Impersonation** (curl_cffi): بصمة TLS/HTTP2 لمتصفحات حقيقية + اختيار عشوائي من قائمة (`_select_random_browser`) | الحماية الحديثة تطبع بصمة TLS قبل أي كود — الطلب العادي بمكتبة HTTP يتكشف فوراً | محرك http في الخدمة الجانبية يبصم عشوائياً بـ chrome/firefox/safari/edge لكل جلسة + `stealthy_headers` بترتيب رؤوس حقيقي |
| 2 | **سلم التصعيد على الحجب**: `retry_blocked_request()` ينقل الطلب لجلسة stealth عند الحجب، حتى `max_blocked_retries=3` | الأرخص أولاً، والحجب يصعّد للمتصفح — لا ندفع تكلفة المتصفح إلا عند الحاجة | محرك auto: http → stealth → urllib مع جولتين؛ كشف حجب بنفس أكواد Scrapling {401,403,407,429,444,500,502,503,504} + بصمات محتوى ("Just a moment", "access denied", "captcha"...) |
| 3 | **Cloudflare Turnstile Solver** (`_cloudflare_solver`): كشف نوع التحدي (non-interactive → انتظار "Just a moment..." ليختفي؛ interactive → إيجاد iframe التحدي + نقرة بشرية بإحداثيات عشوائية ±26px وتأخير 100-200ms) | التحديات غير التفاعلية تُحل بالانتظار الذكي فقط — لا حاجة لنقر | `StealthyFetcher.fetch(solve_cloudflare=True, network_idle=True)` يفعّل نفس الحل داخلياً عند وجود المتصفح |
| 4 | **AutoThrottle**: تأخير لكل دومين = زمن الاستجابة/التزامن المستهدف، يُضاعف عند الحجب، يحترم `Retry-After`، ويعود تدريجياً | الزحف بلطف يمنع الحجب أصلاً — ويمنع استنزاف مواقع العملاء | `DomainThrottle` في الخدمة الجانبية: تأخير أدنى 1ث، مضاعفة عند الحجب (سقف 30ث)، احترام Retry-After، عودة تدريجية عند الاستقرار — **مقاس فعلياً: الطلب الثاني للموقع المحجوب استغرق 32.9ث مقابل 21ث** |
| 5 | **جلسات دائمة** (FetcherSession/StealthySession): كعكات وحالة عبر الطلبات | بعض المحتويات خلف بوابة كعكات | جلسة لكل دومين (LRU 20) في الخدمة الجانبية |
| 6 | **كشف جاهزية المحركات**: Scrapling يرمي ModuleNotFoundError إذا لم تُثبت الملحقات | معرفة ما هو متاح قبل المحاولة توفر عشرات الثواني | `STEALTH_READY` — فحص مسارات camoufox عند الإقلاع؛ إن غاب المتصفح يُستثنى من السلم (خفض زمن صفحة محجوبة من 21-33ث إلى 6.6ث) |
| 7 | **ProxyRotator / DNS-over-HTTPS** | ندرس لاحقاً عند التوسع الكبير | 🔲 مستقبلاً (نحتاج مزود بروكسيات فقط عند نطاق واسع) |

### ترقيات العقدة (NestJS) بنفس الروح

- **فك ضغط gzip/deflate يدوياً** (undici لا يفك الضغط تلقائياً) — فيدات مضغوطة تعمل.
- **كشف الترميز**: charset من الرأس أو meta + جدول **windows-1256** مدمج (فيدات عربية قديمة) — بلا تبعيات.
- **كشف الحجب + Retry-After + إعادة محاولة بتراجع عشوائي (jitter)** في الجلب المباشر.
- **كشف "الفيد يعيد صفحة ويب"**: رسالة عربية واضحة بدل تحليل صامت فاشل.

### نتائج اختبار E2E المسجلة

| السيناريو | النتيجة |
|---|---|
| فيد CSV عادي | ✓ 3 منتجات جديدة |
| فيد **gzip** | ✓ فُك ضغطه وأسماء عربية سليمة |
| فيد **windows-1256** | ✓ فُك ترميزه (لحاف قطن ملكي...) |
| رابط يعيد HTML | ✓ "الرابط يعيد صفحة ويب وليس فيد بيانات" |
| رابط محجوب 403 | ✓ خطأ موثق "(محجوب)" + خنق الدومين |
| سلم المحركات | ✓ urllib يتولى عند تعذر http/stealth |
| إعادة مزامنة | ✓ 0 تغيير (idempotent) |

## التكامل المنفَّذ عندنا (سلسلة تدرّج بلا انقطاع)

```
طلب زحف (من محرر المعرفة)
  → 1) خدمة Scrapling الجانبية v2: http(بصمة TLS عشوائية) → stealth(يحل Cloudflare) → urllib
        + كشف حجب + خنق تلقائي + جلسات دائمة + احترام Retry-After
  → 2) الجلب المباشر المحسّن في NestJS (فك ضغط + ترميز + حجب + إعادة محاولة) [لو الخدمة مش متاحة]
```

- الخدمة: `services/scrapling-crawler/` (Python stdlib server — صفر تبعيات خادم إضافية)
- الربط: `SCRAPLING_URL` في بيئة الـ API — فارغ = الزاحف المدمج فقط (التطوير)
- الإنتاج: `docker compose --profile scrapling up -d` — الخدمة داخلية فقط

## الأمان (معايير دقيقة)

1. **حارس SSRF**: `isPrivateHost()` يمنع زحف `localhost/10.x/172.16-31.x/192.168.x/169.254.x`
   — `CRAWL_ALLOW_PRIVATE=true` في الديمو فقط (لاختبارنا المحلي)، **`false` في الإنتاج**.
2. حدود: 10 روابط/طلب · مهلة 30 ثانية/صفحة · سقف 2MB للـ HTML · مخصص للمشرفين (RBAC).
3. الخدمة الجانبية غير مكشوفة للإنترنت (expose داخلي فقط).

## الاختبار الفعلي

- ✅ الزحف عبر خدمة Scrapling (محرك HTTPX — المتصفح غير متاح في بيئة الاختبار الرملية)
- ✅ التدرّج للزاحف المدمج عند تعطيل الخدمة
- ✅ حارس SSRF يرفض العناوين الخاصة في وضع الإنتاج

## اقتراحات تحسين مستقبلية (مرتبة بالأثر)

1. **زحف كتالوج CS-Cart عبر SitemapSpider + adaptive selectors** — التقنية المميزة لـ Scrapling (العناصر تتبع نفسها عند تغيير تصميم الموقع): تتكيف مع تحديثات ثيمات عملائنا.
2. **capture_xhr**: التقاط بيانات المواقع التي تجلب كتالوجها عبر XHR بدل HTML (شائع في المتاجر الحديثة).
3. **تجزئة الفيد**: مزامنة متزايدة (آخر external_id) للفيدات الضخمة بدل الجلب الكامل.
4. **بروكسيات دوّارة** (ProxyRotator) عند تجاوز ~50 عميلاً — مع DoH لمنع تسريب DNS.
5. **جدولة ذكية**: تأجيل المزامنة ساعات الذروة المصرية احتراماً لمواقع العملاء.
6. **تنبيه عند الحجب المتكرر**: لو دومين عميل حُجب 3 مرات متتالية → تنبيه (جسر جاهز عبر Alerter).

## خارطة استخدام مستقبلي

- **زحف كتالوج عملاء CS-Cart** عبر `SitemapSpider` + `adaptive` (التحديث التلقائي للمعرفة)
- **ShopifySpider** لعملاء Shopify المستقبليين (منتجات JSON مباشرة)
- **capture_xhr**: التقاط بيانات المواقع التي تجلب كتالوجها عبر XHR بدل HTML
